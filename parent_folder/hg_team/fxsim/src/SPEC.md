# fxsim: the shared contract (owner: wled-main-6c). Every agent in this folder follows it

Goal: animated in-browser previews of WLED 1D effects, so the /home phone page can show how an effect
looks before the user taps it. The previews must use the **real colours**: palettes come from the device's
`GET /json/palx?page=N` (wled00/json.cpp:983), plus the segment's 3 colours and its brightness.
They must also move like the device: the same `strip.now` maths, so speed and intensity match.

## Effect function: `fn(S, E)`, called once per frame (the C effects are `void mode_x(void)`)

Rename these when porting:

| `SEGENV.call/step/aux0/aux1/data` | `E.call`, `E.step`, `E.aux0`, `E.aux1`, `E.data` |
| `SEGENV.allocateData(n)` | `E.allocateData(n)`: always returns true, gives `E.data` = Uint8Array(n), zeroed when (re)allocated |
| `SEGLEN`, `SEGMENT.vLength()`, `SEGMENT.length()` | `S.len` |
| `SEGCOLOR(n)` | `S.col[n]` (uint32 `0xWWRRGGBB`) |

| `PALETTE_SOLID_WRAP`, `PALETTE_MOVING_WRAP`, `paletteBlend` | `S.PALETTE_SOLID_WRAP` (false), `S.PALETTE_MOVING_WRAP` (speed != 0), `S.paletteBlend` (0) |
| `strip.getBrightness()`, `getCurrSegmentId()`, `getActiveSegmentsNum()`, `getSegmentsNum()`, `getMaxSegments()` | same names on `S` (bri, 0, 1, 1, 32) |
| `getAudioData()` + `um_data->u_data[k]` | `S.audio()`: `{volumeSmth, volumeRaw, fftResult (Uint8Array 16), samplePeak (0/1), FFT_MajorPeak (Hz), my_magnitude, maxVol, binNum}` (u_data[0..7]); maxVol/binNum are writable like `*maxVol`. A synthetic ~120 BPM song (kick, hi-hat, snare, mids) |

`E.s`: a plain object, reset to `{}` whenever the effect (re)starts. Use it for state that C keeps in structs
cast onto `SEGENV.data` (sparks, ripples, balls, ...). You may keep `E.data` for plain byte arrays.
Always keep the C "allocation failed" guards out: allocation never fails in JS.

Segment methods on `S` (core implements exactly these, same meaning as FX_fcn.cpp / FX.h):
`setPixelColor(i, c)`, `setPixelColor(i, r, g, b, w=0)`, `getPixelColor(i)`, `fill(c)`, `fade_out(rate)`, `fadeToBlackBy(n)`,
`blur(amount, smear=false)`, `addPixelColor(i, c, preserveCR=true)`, `blendPixelColor(i, c, blend)`, `fadePixelColor(i, fade)`,
`color_from_palette(i, mapping, moving, mcol, pbri=255)`, `color_wheel(pos)`, `gamma8(v)`, `move(dir, delta, wrap)`,
`allocateData` lives on `E` (no 1D port needed `wu_pixel`, so it is not in core).
Out-of-range indices are ignored, as on the device. The pixel store is `S.px` (Uint32Array(len), 0xWWRRGGBB), kept between frames like the device's segment buffer.

## Integer semantics: the most common porting bug

C wraps silently and JS doesn't. Mirror the C types exactly:
- `uint8_t x = ...` → `x = (...) & 0xFF`; `uint16_t` → `& 0xFFFF`; `uint32_t`/`unsigned` → `>>> 0`; `int16_t` → `(v << 16) >> 16`; `int8_t` → `(v << 24) >> 24`
- `aux0` / `aux1` are uint16: mask on every assignment. `step` is uint32.
- Integer division → `Math.trunc(a / b)` (C truncates toward zero); `>>` on possibly negative values follows C (arithmetic shift) → JS `>>` is fine for int32
- 32-bit multiplies that can overflow → `Math.imul(a, b) >>> 0`
- `float` maths stays float. `(int)f` → `Math.trunc(f)`
- A `static` local in C → a closure variable in your file (note it's shared across segments, same as C)
- `random8()`, `hw_random8(a,b)` and the rest come from `FXS.H`; never use Math.random directly (the core seeds its PRNG)

Local copies of FX.cpp's static helpers (`chase()`, `running()`, `blink()`, `color_wipe()`, `twinkle...`) belong in the port file that uses them.

## Registry and preview API (core.js)

- `FXS.add(name, fn, opts)`: `name` = the exact effect name (the metadata text before `@`). `opts`: `{audio:true}` for v/f effects, `{static:true}` if it does not animate on the device, `{pal:n}` default palette
- `FXS.has(name)`, `FXS.get(name)` (`{fn, opts}`), `FXS.names()`, `FXS.hasPal(id)` (palx data loaded)
- `FXS.setPalettes(p)`: merges a palx `"p"` object `{id: [[pos,r,g,b],...] | ["r",...] | ["c1",...]}`; callable repeatedly (page by page)
- `FXS.makeSeg(o)` returns `{S, E, fx, t}`; `FXS.set(seg, o)` changes settings; `FXS.step(seg)` runs one frame at the segment clock `seg.t`
  (starts at `o.t0`, default 600000 = 10 min uptime, then advances by `S.frametime * o.rate`); `FXS.step(seg, t)` runs it at an absolute time t.
  `o` = `{fx, sx, ix, c1, c2, c3, o1, o2, o3, col, pal, bri, len, dpal, t0, rate}` (col items: an int `0xWWRRGGBB` or `[r,g,b(,w)]`;
  `pal` = palette id; defaults sx=128, ix=128, c1=128, c2=128, c3=16, len=30, bri=255, col `[0xFFA000, 0, 0]`).
  `dpal` = what palette 0 (Default) shows (Segment::_default_palette): `o.dpal`, else `opts.pal`, else the built-in DPAL map of the "pal=" metadata, else 6 (Party).
  `rate` (default 1) fast-forwards `S.now` only; effects that count frames then run slower than on the device.
- Palettes: ids 1-5 are built from the segment colours as in `Segment::loadPalette()` (1 = random, re-rolled every 5 s and blended);
  a missing palx id falls back to a rainbow and sets `S.palFallback`.
- `FXS.preview(canvas, o)` returns `{seg, set(o), stop(), pause(), resume()}`: one shared requestAnimationFrame loop runs one step per `S.frametime` ms
  (at most 3 catch-up steps per animation frame), **only while the canvas is visible** (IntersectionObserver) and `!document.hidden`.
  Changing `fx` or `len` restarts the effect state; slider or colour changes don't. `FXS.draw(canvas, seg, {bri, bg})` paints one still frame the same way.
- `FXS.audio.set({bpm, level})`: tempo and loudness of the simulated song for all segments (level 0 = silence).
- Unknown effect name: a fallback (palette scroll at the given speed), flagged by `FXS.has()` returning false, so the page can show "≈".
- Drawing = colour on screen `shown = c * (bri/255)^(1/2.2)` (bri 0 = black). The W channel is added onto RGB. The same rule is used
  by 2a's real-device stream, so both look identical.

## Tests: `node check.js [--golden] [fx_p1.js ...]` (no DOM)

For every registered effect: 3 slider sets (metadata defaults, all 0, all 255 incl. checks) × len 30 and 150 × 500 frames, seeded RNG.
Fails on: an exception, a non-integer colour or index passed to setPixelColor/addPixelColor/blendPixelColor/fill, a colour outside 0..0xFFFFFFFF,
`E.aux0/aux1` outside uint16, `E.step` outside uint32, no change in any run for an effect that animates on the device
(static ones: a list in check.js or `{static:true}`), and > 2 ms average per frame at len 150. Exit code 1 on any FAIL.
`--golden` prints two frame-hash columns per effect, to compare refactors.
It also prints a size table: gzip bytes of each effect's source, plus totals per file and overall (terser is available in the repo's node_modules for a minified estimate).
